bcore-release.aar 里的 classes.jar 已打补丁（Apache-2.0 源码对应的字节码，只改一个方法）。

BlackBoxCore.getProcessName(Context) 原来只查 ActivityManager.getRunningAppProcesses()。
在 HyperOS / Android 15 的 Application.attachBaseContext 里，这个列表经常是 null 或不含当前 pid，
方法抛 RuntimeException("processName = null")，doAttachBaseContext 失败，VirtualEngine.available 一直是 false。

补丁后的方法体：
  aload_0
  invokestatic com/parallelspace/parallel_space/ProcessNameCompat.get(Landroid/content/Context;)Ljava/lang/String;
  areturn

重新打补丁（替换了上游 AAR 之后）：
  解出 classes.jar 里的 top/niunaijun/blackbox/BlackBoxCore.class
  javac -cp asm-9.7.1.jar android/tools/PatchBlackBoxProcessName.java
  java -cp asm-9.7.1.jar:. PatchBlackBoxProcessName BlackBoxCore.class
  jar uf classes.jar top/niunaijun/blackbox/BlackBoxCore.class
  再打回 AAR

不要改 ProcessNameCompat.get 的类名或方法签名。

1.3.16 第二个补丁：TaskDescriptionCompat.getTaskDescriptionLabel(int, CharSequence)

原实现 String.format("[B%d]%s", userId, label)，最近任务里显示「[B0]应用名」。
补丁后方法体：iload_0; aload_1; invokestatic com/parallelspace/parallel_space/TaskLabelCompat.label(ILjava/lang/CharSequence;)Ljava/lang/String;; areturn
TaskLabelCompat 读宿主 files/clone_names.json（键 包名#userId），没有自定义名时返回原名，userId>0 时加「 分身N」。

重新打补丁：
  解出 top/niunaijun/blackbox/utils/compat/TaskDescriptionCompat.class
  javac -cp asm-9.x.jar android/tools/PatchBlackBoxTaskLabel.java
  java -cp asm-9.x.jar:. PatchBlackBoxTaskLabel TaskDescriptionCompat.class
  jar uf classes.jar ...；再打回 AAR
不要改 TaskLabelCompat.label 的类名或方法签名。

1.3.35 第三个补丁：分身设备标识与通知隔离。

AndroidIdProxy / ISettingsProviderProxy 的 getWho() 是 null，injectHook 直接返回，那些类没有挂上。
分身读 Settings 实际走 ContentProviderDelegate 包住的
  top/niunaijun/blackbox/fake/service/context/providers/SystemProviderStub
  top/niunaijun/blackbox/fake/service/context/providers/ContentProviderStub
补丁把它们的 invoke 改名为 invokeOriginal，新的 invoke 在原逻辑之后调用
  com.parallelspace.parallel_space.CloneIdentityCompat.rewrite(Object, Method, Object[])
只有分身进程、并且该实例打开了隔离时，才替换 android_id。

通知走 INotificationManagerProxy（这个代理会替换 NotificationManager.sService，是通的）。
补丁改了 invoke，以及 Enqueue/Cancel/Create/Delete/Get 这些 hook，改去调用
  com.parallelspace.parallel_space.CloneNotificationCompat
的 before / enqueue / cancel / createChannels / createGroups / deleteChannel / deleteGroup / getChannel / getChannels / getGroups。
enqueue 和 cancel 仍把真实服务对象（hook 的第一个参数）交给系统，避免 NotificationManager.notify 再进代理。
FALLBACK 表示这次不处理，继续原来的 BlackBox 通知服务。

不要改上述类名和方法签名。proguard-rules.pro 里有对应的 keep。

重新打补丁（替换了上游 AAR 之后）：
  解出 classes.jar
  javac --release 17 -cp asm-9.7.1.jar:asm-tree-9.7.1.jar:asm-analysis-9.7.1.jar android/tools/PatchBlackBoxIsolation.java
  java -cp asm-9.7.1.jar:asm-tree-9.7.1.jar:asm-analysis-9.7.1.jar:. PatchBlackBoxIsolation classes.jar
  把 classes.jar 打回 bcore-release.aar（只替换这一个条目）
可重复执行。补丁会用 ASM Analyzer 检查改过的类。
